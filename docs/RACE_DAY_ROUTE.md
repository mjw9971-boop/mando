# 대회 당일 — 경유점 CSV → route.pkl 한 페이지

이 문서만 보고 끝낼 수 있게 쓴다. 배경 설명은 맨 아래에만 둔다.

## 0. 한 줄 요약

```bash
python3 tools/build_route.py data/lane_graph.pkl <CSV> -o data/route.pkl
```

**rc=0 이고, 리포트 `[2]` 머리의 "짝 해석" 과 짝 구간 표가 실제 코스와 맞으면 끝이다.**

---

## 1. 절차

### ① CSV 받으면 먼저 점 개수를 센다

```bash
wc -l <CSV>          # 헤더 한 줄을 빼고 세는 것을 잊지 말 것
```

- **짝수** → 주최 공식 형식 `[시작, (진입,진출)×N, 종료]`. 그대로 간다.
- **홀수** → 해석이 둘이다. `auto` 가 고르지만 ②에서 **반드시 눈으로 확인**한다.

### ② 빌드하고 리포트 `[2]` 머리를 본다

```
[2] 교차로 짝 구간   짝 해석: offset 1 (auto)
    근거: 짝수 8점 — 주최 공식 형식 (offset 1)
    junction 경유: 짝 1.00 (3개) / 비짝 0.50 (4개)
```

읽는 법:

| 줄 | 정상 | 이상하면 |
|---|---|---|
| `짝 해석: offset N (auto\|forced)` | offset 이 찍혀 있다 | `없음` 이면 ④ |
| `junction 경유: 짝 X` | **정확히 1.00** | **1.00 미만이면 그 해석은 틀렸다** → ④ |
| `/ 비짝 Y` | 짝보다 낮다 | **짝·비짝이 둘 다 1.00 이면 한 칸 밀린 것** (경고가 자동으로 뜬다) |

> `짝 1.00` 은 "짝 구간이 전부 교차로 연결로를 지난다" 는 뜻이다. 기준 CSV
> 26개 66짝 실측에서 **정답 해석은 예외 없이 1.00** 이었다 (2026-09-05, 작업22).
> 0.75·0.93 처럼 "가까운" 값이 나오면 그건 정답이 아니라 **한 짝이 통째로
> 빠졌다**는 신호다.

### ③ 짝 구간 표의 회전 방향을 실제 코스와 대조한다

```
  seq   2→3    junction=[19]  Δheading=  +96.5°  좌회전  차로 2개  회전 OK ((429, 0, 2)→(604, 0, -1), 44 m)
  seq   4→5    junction=[3]   Δheading=  -99.2°  우회전  차로 2개  회전 OK ((420, 2, -1)→(797, 0, -1), 27 m)
  seq   6→7    junction=[10]  Δheading=  -90.3°  우회전  차로 1개  회전 OK ((6027, 0, -1)→(6027, 0, -1), 26 m)
  seq   8→9    junction=[20]  Δheading=  -84.2°  우회전  차로 2개  회전 OK ((465, 0, 2)→(836, 0, -1), 34 m)
```
(위는 `tests/fixtures/venue_20260903_waypoints.csv` = 9/3 대회장 배포본의 실제 출력이다.)

**코스도를 보고 좌/우/직진이 맞는지만 확인하면 된다.** 틀리면 ④.

같은 표에서 **`회전 X` / `[오류]` / `junction 차로를 안 거친다` 가 한 줄이라도
있으면 그 해석은 버린다** — `junction 경유: 짝` 이 1.00 이어도 그렇다. 짝
구간 하나가 다른 교차로를 우연히 지나면 비율만으로는 1.00 이 나온다
(작업22 실측: 형식 위반 CSV 3건이 이 방식으로 자동 판정을 통과했다).

### ④ 안 맞거나 "짝 해석: 없음" 이면 강제 재빌드

```bash
# 첫 점이 곧 진입점이면
python3 tools/build_route.py data/lane_graph.pkl <CSV> --pair-offset 0 -o data/route.pkl
# 첫 점이 출발점이면 (주최 공식 형식)
python3 tools/build_route.py data/lane_graph.pkl <CSV> --pair-offset 1 -o data/route.pkl
```

두 offset 을 다 돌려 보고 **아래 순서로** 고른다.

1. **빌드 실패한 offset 은 탈락.** (`RouteError`)
2. **`junction 경유: 짝` 이 정확히 1.00 인 offset 만 남긴다.** 1.00 미만은
   짝 하나가 교차로를 안 지난다는 뜻이라 그 해석은 틀렸다.
3. 남은 것 중 **짝 표에 `회전 X` / `[오류]` / `junction 차로를 안 거친다` 가
   없는 쪽**을 쓴다. 둘 다 있으면 적은 쪽.
4. 그래도 하나로 안 좁혀지면 ③ 의 회전 방향을 코스도와 대조한다.

**둘 다 2번을 못 넘거나, 남은 쪽에도 `회전 X`/`[오류]` 가 있으면 짝 구조가
없는(또는 깨진) CSV 다.** 주최에 점 개수를 확인하고, 그래도 그대로 가야 하면
`--pair-offset none` 으로 두되 **교차로 내부 차선변경 금지가 안 걸린다**
(채점 항목 6 위험) — ③ 의 회전 구간에서 차선변경이 나오는지 [4] 이벤트를
직접 본다.

> `짝 해석: 없음` 이면 리포트가 `!!!!` 박스로 크게 경고한다. 놓칠 수 없다.

**마지막 점이 종료점이 아닐 수 있다.** `[시작, (진입,진출)×N]` 으로 끝나는
홀수 CSV(= 마지막 점이 곧 진출점)도 정상이다. 이때 `finish_xy` 가 그 진출점이
되어 코스가 짧아 보이지만 빌드는 문제없이 된다 — 작업22 실측 23/23 rc=0.
`[1]` 의 마지막 seq 가 짝 표에도 등장하면 이 형태다.

### ⑤ rc 를 확인한다

`rc != 0` 이면 `batch_run` 이 이 경로를 **통째로 버린다**. 리포트에서 `[오류]` 를 찾는다.

| 오류 | 뜻 | 손보는 곳 |
|---|---|---|
| `창이 20 m 미만` | 차선변경 전이거리를 못 채운다 | 경유점을 옮겨 다른 차로 유도 |
| `누적 N m > 차로 M m` | 한 차로 안에서 차선변경을 여러 번 해야 한다 | 위와 같음 |
| `교차로 내부에서 차선변경` | 짝 해석이 틀렸을 수 있다 | ④ 로 |
| `회전 X` | 짝 진입→진출이 안 이어진다 | ④ 로. 그래도 안 되면 경유점 조정 |
| `R_min < 5.65 m` | 그 연결로를 차량이 못 돈다 | 경유점을 옮겨 다른 연결로 유도 |

## 2. 옵션 요약

| 옵션 | 기본 | 쓸 때 |
|---|---|---|
| `--pair-offset {auto,none,0,1}` | `auto` | ④ |
| `--radius <m>` | 8 | 경유점이 차로에서 멀어 "반경 내 차로 없음" 이 날 때 |
| `--ego-yaw <rad>` | 자동추정 | 출발 헤딩이 반대로 잡힐 때 (9910 실측값을 넣는다) |
| `--warn-dev <m>` | — | 경유점 이탈 임계를 고정하고 싶을 때 |

당일 조정 가능한 params (`config/params.yaml`):

| 키 | 기본 | 뜻 |
|---|---|---|
| `route.pair_auto_min_ratio` | 0.75 | auto 가 채택할 최소 junction 비율. **1.00 = "모든 짝이 교차로를 지나야 채택"** — ②의 사람 판정 기준과 같아진다 |
| `route.pair_auto_min_margin` | 0.50 | 승자−패자 최소 차이. **올리지 말 것** — 정답 표본 하나가 정확히 0.50 이라 0.51 부터 죽는다 (작업22) |
| `route.min_hop_gap_m` | 20.0 | 차선변경 전이 하나가 먹는 진행거리 |
| `route.check_waypoint_max_dist_m` | 6.0 | 경유점 이탈 경고 임계 |

## 3. 왜 이렇게 하나 (읽지 않아도 된다)

짝 해석이 틀리면 두 가지가 동시에 어긋난다 — **짝 공동 선택**(진입·진출 차로를
같이 고른다)과 **교차로 내부 차선변경 금지**. 둘 다 조용히 틀리기 때문에
"빌드는 됐는데 경로가 이상한" 상태가 된다.

판정 신호는 **짝 구간이 junction 차로를 실제로 지나는 비율** 하나다.
짝수 기준 CSV 25개 실측(2026-09-04):

| | 정답 offset | 오답 offset |
|---|---|---|
| 짝 구간 junction 경유 | **65/65 = 100 %** | **4/86 = 5 %** |
| `turn_connect` 성공률 | 97 % | 94 % (판별 불가) |
| \|Δθ\| ≥ 25° | 42 % | 9 % (약함) |

margin 은 최소 0.50 · 중앙값 1.00 이었다. 짝 구조가 없는 합성 경로
(`data/test_route_waypoints.csv` 17점)는 0.75 vs 0.50 = margin 0.25 로
자동으로 걸러진다.

임계를 1.00 으로 안 잡은 이유(2026-09-04 판단): "연결로 사이 링크 도로로
이어지는 정당한 짝" 이 43개 중 6개 있었다. 당일 CSV 가 7/8 로 나와도 통과
하도록 0.75 로 뒀다.

**이 근거는 2026-09-05(작업22)에 재확인 결과 성립하지 않는다.** 그 6개는
전부 `data/test_route_waypoints.csv` — `make_test_route.py` 가 만든 **17점
합성 파일**로, 짝 구조 자체가 없다(진입·진출이 같은 차로 `(173,0,-1)→(173,0,-1)`
인 "짝" 이 그 안에 있다). 실제 배포·시나리오 계열 짝수 CSV **26개 66짝을
현재 코드·현재 지도로 다시 재면 junction 미경유는 0개**다. 옛 코드·옛 지도
(cf1746d, 지도 022b9f4)로 돌려도 복원 가능한 25짝에서 0개였다.

> 2026-09-04 14:35 시점의 `scenarios/*.csv` 는 `.gitignore` 대상(생성물)이라
> 되살릴 수 없다. 43짝 중 그 몫은 재현이 불가능하므로 "6개가 전부 합성
> 파일에서 나왔다" 는 **최소 4개까지만 확정**이고 나머지 2개는 미확인이다.

### 홀수 CSV 자동 판정 실측 (2026-09-05, 작업22)

짝수 원본 23개에서 점 하나를 빼 정답을 아는 홀수 표본 115개를 만들어 CLI 로 전수 채점했다
(`tools/gen_odd_waypoints.py`, `tests/fixtures/odd/`).

| 표본 유형 | n | 적중 | none 폴백 | 오답 |
|---|---:|---:|---:|---:|
| B `[(진입,진출)×N, 종료]` (정답 offset 0) | 23 | **23** | 0 | 0 |
| C `[시작, (진입,진출)×N]` (정답 offset 1) | 23 | **23** | 0 | 0 |
| D 형식 위반 (정답 none) | 69 | 28 | — | 41 |

- **정상 홀수 CSV 는 46/46 맞춘다.** 정답 offset 의 짝 비율은 46개 전부 정확히 1.00.
- D 오답 41건 중 38건은 **보수적 과폭**(참 교차로는 전부 금지 안에 들어가고 경유점
  한 칸만 넓다). 실제 위험은 3건뿐이고 전부 **첫 진출점이 빠진 CSV** 였다.
- 그 3건은 `junction 경유: 짝` 이 1.00·0.93·0.75 로 나왔다 —
  **①에서 "정확히 1.00" 을 요구하면 2건, ③의 `회전 X` 확인까지 하면 3건 전부** 걸러진다.
  이것이 위 ④ 절차를 비율 하나에서 3단계로 바꾼 이유다.

**소요 시간**: 짝수 CSV 는 시험 빌드를 안 하므로 예전과 같다(~0.65 s).
홀수는 시험 빌드 2회가 붙어 **+0.03 ~ +0.16 s** 늘어난다. 무시해도 된다.

## 4. `route.pkl` 안에 뭐가 들어 있나 (참고)

당일에 볼 일은 거의 없지만, 이상할 때 확인할 곳:

| 필드 | 뜻 |
|---|---|
| `pair_offset` / `pair_offset_source` / `pair_offset_why` | 어느 짝 해석으로 지었나 (위 ②와 같은 내용) |
| `infeasible_forced` | 통행 금지 연결로를 대안이 없어 그대로 통과시킨 기록 |
| `valid_entry_lanes` | 짝이 아닌 세그먼트마다 "다음 짝 진입에 유효한 차로 집합" |

`valid_entry_lanes` 의 각 항목:

| 키 | 뜻 |
|---|---|
| `target` | `'pair'` 다음이 짝 / `'finish'` 마지막 세그먼트 / `None` 다음 제약 없음 |
| `lanes` | 그 차로에 있으면 차선변경 없이 다음 진출점까지 갈 수 있는 진입 차로들 |
| `turn` | 다음 짝이 `left` / `right` / `straight` |
| `chosen` · `in_set` | 경로가 실제로 고른 진입 차로와 그게 집합 안인지 |

**빈 집합의 뜻이 두 가지다** — `target='finish'` 면 "차로 제약 없음"(정상),
`target='pair'` 면 **"통행 가능한 진입 차로가 없다"**(통행 금지 연결로뿐).
후자면 `infeasible_forced` 를 함께 본다.
