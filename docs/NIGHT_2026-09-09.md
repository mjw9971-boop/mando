### (a) 객체 → 차로 매칭

- 객체에 **차로 정보가 없다.** `run_agent._log_objects` 가 `lane=None` 으로
  박아 넣고([run_agent.py:372](../run_agent.py#L372)), `VtdActor` 에도 차로

  ([lanegraph.py:443](../vtd_adapter/lanegraph.py#L443)) 와
  `lg.locate(x, y, yaw, prefer=...)` → 최적 차로 1개
  ([:491](../vtd_adapter/lanegraph.py#L491)). `locate` 는 **1개만** 주므로
  걸친 차로를 못 잡는다 → 세 점(중심 · 좌우 폭 끝) 각각 `locate` 해서
  **합집합**을 취하는 방식이 맞다.
- **둘 곳**: `VtdWorld.update` 가 객체 수신의 단일 관문이다
  ([world.py:73](../vtd_adapter/world.py#L73)) — 여기가 자연스럽지만
  **`VtdWorld` 는 `lg` 를 안 갖고 있다**(`__init__(cfg)` 뿐). `run_agent` 는
  `self.lg` 와 `self.world` 를 둘 다 쥐고 있으므로
  ([run_agent.py:199·207](../run_agent.py#L199)) 생성 시 주입하면 된다.
  → **결정: `VtdWorld(cfg, lg=None)` 로 선택 주입**, `lg` 가 없으면 매칭을
  건너뛴다(목 테스트가 lg 없이 world 를 만든다 — 깨면 안 된다).
- 교차로 안: 연결로는 `neighbor` 가 없어 차로 지도의 hop 이 성립하지 않는다.
  `junction != -1` 이면 매칭은 하되 **passable=False** 로 둔다(시프트 금지는
  이미 `_try_overtake_inner` 의 `reject='junction'` 이 한다).
- 소멸 차로: 폭 < 2 m 는 `passable=False`. 폭은 `lg.lanes[k]['width']` 배열이라
  **해당 s 지점 값**을 봐야 한다(평균 아님 — 테이퍼는 끝에서 0 이 된다).

### (b) 큐 제외

`_is_queue_v2` 는 **bool 하나만** 돌려준다
([kr_rules.py:1369](../team_code/kr_rules.py#L1369)) — 객체 단위 판정을 꺼낼

`_tick_queue` 가 참인 동안 **`_tick_corridor` 에 든 id 를 차로 지도에서 제외**.
객체별 재판정을 새로 만들면 억제 기준이 두 벌이 된다(CLAUDE.md 위반).
한계: 큐가 **내 차로**에만 성립할 때 옆 차로 정지차까지 빠질 수 있다 —
`_tick_corridor` 가 자차 회랑 기준이라 애초에 옆 차로 객체가 안 들어온다.
따라서 실제로는 안전한 쪽으로만 틀린다.

### (d) 두 칸 램프 — **이미 된다**

`shift_route_smoothly` 가 `_shift_target_wp(idx, side, n_steps)` 를 쓰고, 그
함수는 **이웃을 n_steps 만큼 따라간다**
([route.py:663](../vtd_adapter/route.py#L663)). 지금은 `n_steps` 가
`_shift_target_steps` 에서 "현재 밀린 칸수 k + 1" 로만 나온다(항상 한 칸씩).
→ **필요한 것은 "목표 hop 수"를 넘기는 인자 하나뿐**이다. 좌표 계산·전이·
`lat_shift`(지시등 입력) 갱신은 전부 그 경로를 그대로 탄다.

- 회랑 폭·점선 2개 연속: `_dashed_ahead_m(lg, ego_lane, side, ...)` 는 **한
  칸** 기준이라 2 hop 이면 중간 차로에서 한 번 더 재야 한다 (게이트 보강 필요).
- 램프 길이: `trans_m = max(ot_trans_m, shift_k_s·v)` 는 칸수와 무관하다 →
  **칸수 배로 늘려야** 횡가속이 같다 (커밋 B 에서 `칸수 × 차로폭 / a_lat`).
- 지시등: `lat_shift` 가 변위 크기로 들어가므로 2 칸이면 값만 커지고 부호는
  같다 → **한 번 켜고 유지**가 자연히 성립한다.

### (e) 복귀 없음일 때 지시등·속도캡

**`_lat_adopt` 는 존재하지 않는다** (지시안의 이름은 가정이었던 것으로 보인다).
현재 "기준 배열"은 `planner.original_route_points` + `planner._lat_build` 이고,
`lat_shift[idx] = _lat_build[idx] ± d` 로 매 틱 갱신된다
([route.py:716](../vtd_adapter/route.py#L716)). 즉 **오프셋을 0 으로 되돌리면
지시등이 역방향으로 켜진다** — 지시안이 지적한 `route.py:434` 전례와 같은 축이다.

→ 복귀 없음을 하려면 **`original_route_points`·`_lat_build` 를 새 차로 기준으로
갈아끼우는 함수가 새로 필요하다** (커밋 C 의 핵심). 손댈 곳 3 : `lat_shift`
기준(`_lat_build`), `_shift_target_steps` 의 k 계산 기준, `planned_lateral_offsets`.

### (g) 감속 후보 자리

`apply` 의 min() 사다리 [:4540 부근](../team_code/kr_rules.py#L4540) —
`_lc_speed_cap` 바로 옆에 넣는다. **[2] 확정 사실대로 상한형**이므로
`cap_cand` 에도 같이 넣어야 `cap_binds` 가 서고 P + `a_cap_dec_max` 축을 탄다.

`planner.lc_ramps`, 회피는 차로 지도). 같은 자리의 별도 후보로 둔다.

### (h) `_chain`·`span_extend` vs `free_run`

- `_chain` 은 **회랑 안 연쇄 병합**이라 `free_run`(차로별 첫 장애물까지 거리)이
  대신하지 못한다. `free_run` 은 "어디까지 비었나", `_chain` 은 "span 을 어디까지
  늘려야 하나" 로 쓰임이 다르다 → **둘 다 유지**.
- `span_extend` 는 활성 span 의 **끝만** 늘리는 사후 보정이다. 차로 지도가
  목표를 처음부터 제대로 고르면 발동이 줄겠지만, 예측 못 한 객체에 대한
  안전망이므로 **유지**.

1. `VtdWorld(cfg, lg=None)` 주입 + 객체 3점 투영 → `actor.lanes`(집합).
2. 차로 지도는 **kr_rules** 에 둔다 (`planner.lg` · `_tick_corridor` ·

**6건 중 1건 침범. 원인은 위상이 아니라 로직이다** — 지시안이 물은 그대로다.

`_yellow_latch` 는 `v ≤ √(2·a_yellow·d_eff)` 로 STOP/GO 를 정한다(`a_yellow=4.0`).
침범 건은 **v 8.06 vs v_allow 8.62 — 여유 0.56 m/s (7 %)** 로 아슬하게 STOP 이
나왔다. 그런데 이 식은 **판정 순간부터 −4.0 이 즉시 걸린다고 본다.** 실제로는
jerk 제한(`jerk_max 2.0 × jerk_dec_mult 3.0` = 0.3 m/s² per tick)이 있어
−4.0 도달에 **0.67 s** 걸리고, 그 사이 평균 감속이 절반이라
**약 v·t/2 = 8.06 × 0.67 / 2 ≈ 2.7 m** 를 더 간다.
여유 0.56 m/s 는 거리로 약 1.2 m 이므로 **부족분 ≈ 1.5 m** — 실측 침범
**+1.59 m** 와 맞는다.

다른 5건은 `v_allow` 여유가 3~4배라 이 오차가 묻혔다. **즉 근접 황색에서만
재현되는 계통 오차**다.

제안 (미적용): 판정 감속을 실효값으로 낮추거나(`a_yellow` 4.0 → 3.0),
`d_eff` 에서 jerk 램프 거리 `v²/(2·a) + v·a/(2·j_eff)` 를 빼고 재는 것.
전자가 한 줄이고 기존 상수 축과 같다. → **아침 판단 필요 3.**

## [4] B3 적색 점멸 일시정지 (항목 9, 중대 −6)

### 채점기 — **이미 구현돼 있었다** (수정 없음)

지시안의 "미구현 표시 제거" 는 해당 없다. `tools/score.py` 의
`detect_blink_stop` ([:996](../tools/score.py#L996)) 이 이미:

- `ITEMS` 에 `(9, 'blink_stop', '적색점멸 일시정지')` 로 **키가 있고**
  (미구현 표시는 **항목 12 횡단보도 정차 금지**다 — 그쪽이 `key=None`),
- 범퍼 기준 `stop_line_front_m` 으로 `scoring.stop_ok_m`(2.0) 안 접근 +
  `stop_hold_s`(0.5) 이상 정지를 보고,
- 선을 **넘기 전**(`front_m ≤ 0`) 정지만 인정하며,
- 위반 등급이 `'major'`(중대) 다.

실측으로도 동작한다 — `logs/batch/20260902_201350` 두 로그 모두
**항목 9 = 1건 −6** 으로 이미 잡혀 있었다 (91/100). 즉 **채점은 맞고 제어기가
안 서던 것**이다.

### 제어기 — 고쳤다

| 파일 | 변경 |
|---|---|
| `vtd_adapter/carla_types.py` | `TrafficLightState.FlashRed = 5` 추가 |
| `vtd_adapter/route.py` | `LIGHT_STATE_MAP_FLASH` (6 → FlashRed), 스위치로 선택 |
| `team_code/kr_rules.py` | `_flash_tick` / `_flash_release`, `_stop_target_raw` 에 FlashRed, `signal_release` 에 합류 |
| `config/params.yaml` | `speed.signal_flash_stop_enable`(false) · `flash_hold_s`(0.8) |

**설계**: 6 → `FlashRed` 는 PDM 에 "녹색이 아닌 것" 이라 PDM 원문 비교문
(`== Red/Yellow/Green/Off`)이 전부 거짓이 되어 **손댈 필요가 없다**.
세우는 것은 `_stop_target_raw` 에 FlashRed 를 더해 **적색과 같은 ④′ 정지
프로파일 축**(`stop_profile_a`)으로 보낸 것이다 — 지시안대로 상한형이 아니다.
유지시간을 채우면 래치가 붙어 `_stop_target_raw` 가 None 이 되고 같은 틱에
`signal_release` 가 PDM 적신호 IDM 도 건너뛴다 = 재출발.

임계는 **새로 만들지 않았다** — `scoring.stop_ok_m` · `score.stop_speed_mps` 를
그대로 읽는다 (같은 주행이 제어기 기준과 채점 기준으로 갈리면 안 된다).

### 도중에 잡은 것 둘 (replay 로 드러남)

1. **PDM 의 적신호 IDM 만으로는 못 선다.** 처음에 매핑만 하고 돌렸더니 점멸
   정지선을 **5.4 m/s 로 통과**했다 (`red_light` 후보가 6.94 → 5.42 까지만
   내려간다). PDM 적신호 IDM 은 차간모형이라 정지 컨트롤러가 아니라는
   기존 주석 그대로다 → ④′ 를 태워야 했다.
2. **부호 규약 반전.** `d_line` 은 뒷축 기준 **남은 거리**(양수)인데
   로그·채점기의 `stop_line_front_m` 은 **음수 = 선 앞**이다. 처음에
   `front_m = d_line − front` 로 써서 판정이 통째로 뒤집혀 있었다.
   → `front_m = front − d_line` 로 채점기와 같은 축에 맞췄다.

## [5] 작업 2 — 커밋 A (차로 지도, 읽기 전용)

`avoid_map.lane_map_avoid_enable` (기본 **false**).

자차 앞 `lane_map_ahead_m`(80 m)를 자차 차로 ±`lane_map_max_hops`(2) 범위에서
차로별로 재 둔다. **아무도 안 읽는다** — `reasons.lane_map` 진단으로만 나가고
후보 선택에 쓰는 것은 커밋 B 다.

| 필드 | 뜻 |
|---|---|
| `free_run[k]` | 그 차로 첫 **정지 객체**까지 거리. 없으면 80 |
| `passable[k]` | 존재 ∧ 같은 방향 ∧ 폭 ≥ 2 m ∧ 교차로 아님 |
| `blocked_by[k]` | 여유를 깎은 객체 id |
| `queue_dropped` | 큐로 빠진 객체 수 |

분석 (a)~(h) 에서 정한 대로 구현한 것:

- **객체 3점 투영** — 중심 + 좌우 폭 끝. 걸쳐 선 차가 두 차로를 다 막는다
  (증상 3). 객체에 차로 정보가 없다는 사실(로그 `lane: null` 은 설계)에 대한 답.
- **폭은 그 지점 보간값** — 평균이 아니다. 소멸 차로는 끝에서 0 이 된다.
- **큐 제외는 기존 규약 그대로** — `_tick_queue` 가 참인 틱에 `_tick_corridor`
  의 id 를 뺀다. 객체 단위 큐 판정을 새로 만들지 않았다 (억제 기준 두 벌 금지).
- **"정지 객체" 임계는 `overtake.blocker_speed_max`** 를 그대로 읽는다.

검증: `tests/test_lane_map.py` 15건 (이웃·여유·걸침·폭·교차로·큐 제외),
replay 56건 off 지문 **bit 동일**, pytest 1497 passed / 0 failed.

**커밋 B·C 는 하지 못했다** — 아래 참조.

### 커밋 B·C — **하지 않았다. 여기서 멈췄다.**

**막힌 것: 검증 수단이 없다.** 지시안이 B·C 의 합격 기준으로 못박은 것은
`tools/avoid_sim.py` 의 **10개 시뮬 케이스**(충돌 0 · |t_off| ≤ 0.6 · 조향 포화
0 · 지시등 방향 · 램프 시작 속도 ≤ 20)인데, **그 파일이 없다** — 새로 만들어야
한다. 횡·종 폐루프에 차선변경 램프까지 태우는 시뮬이라 그 자체가 큰 작업이고,
오늘 밤 안에 만들어 10 케이스를 다 태울 수 없다.

검증 없이 B 를 넣는 것은 **하지 않기로 판단했다**. 이유:

1. B 가 손대는 곳이 `_try_overtake_inner` 의 후보 선정과 `_side_pass` 의 side
   루프다 — 게이트 7개 · 2바퀴 · 래치 · 진단이 얽힌 저장소에서 가장 촘촘한
   코드다. 스위치가 false 라도 **켜는 순간 회피 전체가 그 경로**를 탄다.
2. 두 칸 램프는 `route.py` 의 `_shift_target_steps`(현재 "지금 있는 차로에서
   한 칸" 을 스스로 계산한다)에 **hop 수 인자**를 뚫어야 한다. PDM 이식부라
   회귀 범위가 넓은데, replay 지문으로는 **off 만** 검증되고 on 은 시뮬이
   있어야 검증된다.
3. C(복귀 없음)는 분석 (e) 에서 확인했듯 **기준 배열(`original_route_points` ·
   `_lat_build`) 교체 함수가 새로 필요**하고 지시등·속도캡·`_shift_target_steps`
   3곳이 그 기준을 공유한다. 하나라도 어긋나면 지시등이 역방향으로 켜진다
   (항목 13 감점). 이것도 시뮬 없이는 확인이 안 된다.

**남긴 것**: 커밋 A 의 차로 지도가 B 의 재료를 전부 만들어 두었고(`free_run` ·
`passable` · 3점 투영 · 큐 제외), 분석 (a)~(h) 에 **경계와 방법이 다 적혀 있다**.
B 를 이어서 하려면 순서는:

1. `tools/avoid_sim.py` — 10 케이스. 기존 `vtd_adapter` 플래너 + PDM
   `LateralPIDController` + 자전거 모델로 짤 수 있다 (실주행 1차 [2] 때 만든
   추종 시뮬과 같은 얼개).
2. `_shift_target_steps` 에 hop 수 인자 (기본값은 현행식 = 비트 동일).
3. `_lane_map_pick` (트리거·후보·선택·램프 역산) → `_side_pass` 의
   `target = lg.neighbor(...)` **한 줄만** 교체.
4. 감속 후보는 `cap_cand` 에도 넣는다 — 상한형이다 (CLAUDE.md 확정 사실).

→ **아침 판단 필요 5.**
